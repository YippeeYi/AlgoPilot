## 手工只读核验：最小步骤与结果模板

1. 用户先确认 Dashboard 项目是专用测试或生产只读；记录项目别名和日期，输出不要附连接串、邮箱/用户 ID 或密钥。无需向 Codex 提供密码/Token。
2. 执行 [M34_READONLY_DIAGNOSTICS.sql](sql/M34_READONLY_DIAGNOSTICS.sql) 的主查询：**仅 SELECT 与 pg_catalog/pg_indexes/pg_policies 读取**，无 BEGIN/SET/DDL/DML，也不调用任何业务 RPC、cf_secret 或密钥读取。若工具会包事务，由工具管理，不复制写入语句。
3. migrationHistoryVisible 为 true 时，另执行文件末尾注释中的 SELECT version。只需版本列读取权；未授权/不可见填 BLOCKED，不用管理员 DML 作为替代。既有普通只读身份能读相应系统目录即可；不在脚本中创建角色或 GRANT。
4. 与 [本机参考清单](m34/local-schema.json) 比对。清单本轮在 PGlite 18.3 实际执行相同查询：18 个函数、17 表、35 索引、198 约束，并记录 001–010 源文件 SHA-256。函数同时导出 definitionMd5/bodyMd5、SECURITY DEFINER、search_path、PUBLIC/anon/authenticated EXECUTE；表/列读写权限、RLS/策略、索引和已验证约束分列。包含旧思路快照、计划/关联、复盘/请求的结构，仍不读取个人行。只导出代码哈希，不导出函数正文，避免误导出潜在私密字面量。MD5 是结构比对校验，不用于安全签名。
5. PostgreSQL 版本或 pg_get_functiondef 格式不同可导致定义哈希变化；先比较 bodyMd5、参数和 config/ACL，再由操作员在 Dashboard 内检查差异，**不自动放行或修 DDL**。007 的 learning_evidence/candidates 被后续覆盖，应核对当前 010 的有效定义；008 无独立永久对象，仅凭当前候选定义不能证明迁移账本曾执行 008。
6. 用 [hosted-result.template.json](m34/hosted-result.template.json) 回填脱敏结果。缺失对象、哈希不符、RLS false、过宽 EXECUTE/DML、未验证约束均列阻碍。普通 SELECT 系统目录无法确认私有例外表内容、HMAC 实际一致或历史数据内容；不要将这些项改成 PASS。

结构兼容检查关注旧 Session/Thought/Code/Review/Plan 外键与列/约束保留，字段白名单和原函数签名仍有效；新私有表 RLS/无直接 DML。真正的迁移前后个人记录比较仅能在专用测试项目对获准夹具运行，不追加到本次 SELECT 脚本。

HMAC 本轮不读取 private settings、不输出 key/派生 key/密钥 hash。未来若单独获准，可由应用服务器和操作员对一次性域隔离消息独立计算挑战，仅比较相等与否，不使用合法业务 payload、不持久化 proof；或者用专用测试用户的正常签名写入闭环验证。前者需另批私有配置读取权限，后者需远端写入授权，两者当前均未执行。

## 真正托管 E2E：等待授权的具体操作

**目标必须先填明具体专用项目；当前 NOT_SELECTED。** 以下是变更审查清单，不是授权或自动部署脚本：

| 操作 | 目标/变化 | 风险与预期结果 |
| --- | --- | --- |
| 资源准备 | 用户选择已有测试项目，或另行批准免费/付费资源、区域、预算 | 不自动创建资源；确认隔离、配额与清理责任 |
| 缺失迁移 | 手工核验后列实际缺失文件和哈希，才申请应用 001–010 中缺失项 | DDL/锁与兼容风险，先测试备份；不能预设 007–010 都缺失 |
| 签名/站点配置 | 仅批准的测试项目 private settings、APP_URL/Auth Redirect URLs | 密钥/配置变更需独立确认，不把测试 key 写入仓库 |
| 测试 Auth | 两个获准邮箱/用户，真实注册验证、登录/退出/刷新 | Auth 会写远端状态、可能发邮件；Token 仅内存，不记日志 |
| 业务夹具 | 两用户各少量标记偏好、计划、训练/复盘及 YippeeYi 关联 | 只改受验用户，不用生产数据；合成代码若调用 Provider 另批预算 |
| 故障与清理 | 并发、ACK 丢失、撤销、换 Handle、解除/删除各自采集、清理测试夹具 | 仅测试范围可破坏；清理也属于待批准写入，不能扩大删除条件 |

执行时记录真实签发 Token 的 issuer/有效性验证结果，不保存 Token 或仅靠本地 decode 当验签。服务端 getUser 与 Supabase PostgREST 必须实际接收该 Token；不能 SET ROLE/设置 request.jwt.claim.sub 冒充真实 Auth。

1. 两独立浏览器上下文 A/B：注册邮箱确认、登录、退出，未登录 API 应 401；真实过期或测试项目批准的 TTL 下验证刷新和失效恢复，不伪造 claims。邮件恢复和 Redirect URL 记录独立状态。
2. 偏好/训练/计划/复盘写入 A 后，B 读列表无 A 数据，直接访问 A ID 拒绝；B 的正常 JWT 直接 PostgREST DML/官方证据伪造/HMAC 错误应拒绝，错误不泄露正文。
3. 同一 YippeeYi 可各自关联，scope 和授权独立；替换测试 Handle 需另外许可真实公开读取，不擅自抓另一个账号。解除/删除只清本用户采集，原计划/训练/Review 不变。
4. 绑定→同步→partial/EOF 覆盖→开启授权→画像/推荐→撤销：比较数据库 evidence 与 API 引用，撤销前截图/JSON只保留去标识摘要；先冻结同版本请求再撤销，旧在途结果应 PT409，重算无官方引用。AI 复盘授权单独开关，不因官方 OK 解锁 Tutor 或验证代码快照。
5. 并发测试分两栏：至少两个实际数据库 backend 记录锁/CAS/租约/相同请求幂等；另起两个独立 Node 进程/应用实例连接**同一测试项目**，记录匿名实例别名/PID/起止，验证共享 CF 时隙。数据库三连接证据不能填写“应用实例=3”。
6. 实际公开 API 不能人为制造重判/限流/新增提交，不要求参与者提交无意义代码。真实观察与故障注入分别记录；注入超时只丢网络响应，不绕过槽位/租约。缺少真实 Verdict 变化继续 NOT_RUN，单列隔离已验证。
7. 历史兼容先在测试 006 下用真实 Auth 创建明确标记的旧训练/计划/快照，再在获准的缺失迁移之后比对原字段/链接/顺序/代码 hash；不得为验证迁移而回滚生产。Provider/Tutor 成功输出、费用和真人教学质量是独立门禁，未授权则不调用。

[public-cf-replay.json](m34/public-cf-replay.json)：用录制响应经过真实 parse/service/repository/HMAC/007–010 SQL；只有 Supabase 客户端 RPC/HTTP 和 Auth uid 是本地适配替身。注入首批写入后 ACK 丢失、后续尾页 TimeoutError，**保留实际 3 秒 SQL 时隙和 30 秒失败冷却**，没有缩短限流来方便测试。93 条成功批次和 partial 先保存，失败仍保留 40 个可信 OK；继续同检查点取得实际录制 EOF。开启后冷启动 800–1200 候选 2753，撤销后 2771（18 个区间内匹配 AC 被过滤并恢复），官方引用 47→0；画像官方不同题目 40→0，用户 B 仍为空。重复 OK 不变成 41 道题，参考难度仍 1000。此例为本地合成 AlgoPilot 用户的默认冷启动偏好，使用 10 月 12 日题库录制匹配，不代表 YippeeYi 的真实能力、训练意愿或实时题库质量。

此完整本地重放不是浏览器真实 Supabase 操作或部署时长测量；实际网络只上述三次。真实部署的中断、Runtime maxDuration、CF 网络状态和题库刷新并发仍待测试项目；覆盖/检查点文案是否容易理解，也尚无真人理解度评估，不能由布局测试代替。源码路由 maxDuration=120、上游开始前预算 90 秒并不能证明部署计划支持 120 秒。

## 推荐机制与教学边界

本轮固定原八类合成画像和 11,450 题录制，在相同过滤/相同难度/同一证据下比较 600 池和完整兼容池；线上 engine、weights、标注及 001–010 均不改。输出 [reliability-study.json](m34/reliability-study.json)，比较的是当前评分能否找到更高因素分，不是教师认定哪题更好；相同因素分的选题差异也不意味着学习价值相同。

500 训练/200 复盘/500 官方窗口仍有已知长期方向遗失风险；原窗口回归显示 500 次近期练习可挤出旧方向，标签不出现不代表掌握。全历史已知完成排除与画像窗口分开，602 官方 AC/500 分析旧断言保留。不完整历史只排已观察 AC；缺少 AC 不是未做/薄弱证据。Tags-only 匹配及大规模公共关联过度排除风险不能凭这些合成数据否定，用户主动重练可恢复候选，但无真实选手评价证明体验合适。

本轮尚无真实教学质量数据支持调权。五道替代题复核见 [M34_RECOMMENDATION_STUDY.md](M34_RECOMMENDATION_STUDY.md)，1253C 官方展开正文未取得，AI 推导没有自动转入线上 core 标注。

八类完整兼容池规模 2,390–3,229；600 池均包含完整池当轮当前评分选中的前五，首位因素分差为 0。多完成场景在 SQL 候选预算前真实插入隔离的 40 个已做过滤夹具，两个比较池共享相同约束；不把窗口后筛出的 560 项误写成生产预算策略。结论仅限固定录制/合成历史，不证明缺省 600 永远不遗漏更有教学价值的题，也不证明 Tags-only、窗口或大量 AC 的用户体验已通过。

原 extensive 场景虽标名“多计划”，实际函数只生成完成/反馈历史；本轮池对照两侧未注入计划关联，因此不将该对照作为多计划质量证明。既有多计划/关联/去重断言仍由全量回归保留。
