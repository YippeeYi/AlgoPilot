## 2. 502 审核拒绝的可复现条件

历史错误为 `502 REVIEW_OUTPUT_REJECTED`，旧消息将“不可靠验证声明”和“无效行号”合并。**原始失败输出没有保留，无法判断实际命中哪条，未恢复或检查不存在的原文。**

确定性用例以 3 行已保存 AC 快照和更长的追问对照代码为输入：

- 将对照代码第 4–12 行放入 `lineAnalysis`：范围超出 AC，正确拒绝。新版仍拒绝，返回 `reason=invalid_line_range`，没有把快照范围扩展成对照代码范围。
- 合法句“未实际运行，不能保证正确”：原正则含不区分否定的 `保证正确` 分支，会误拒。新版只屏蔽紧邻的明确否定动作/保证，而非删除整句；接受“通过静态推导可知”“假设执行结果为6”“我没有实际运行过代码”等受限静态描述。
- “未实际运行，但我已经测试过代码”“没有运行；测试通过”等仍拒绝；前半句的否定不会豁免后半句正向声明。英文已执行、双重否定和零宽字符控制样本也覆盖。

规则是语言启发式，不是自然语言真实性证明。它可能保守地拒绝某些复杂引述，也可能漏掉未覆盖的改写；不能据 5 个合法表达样本推算真实误拒率。没有放行所有假设句、所有含“静态”字样的段落或任意行号。

## 3. 最小实现变化

`algopilot-ac-review/1.1.0` 在服务端标注 `saved_ac_snapshot`、真实代码哈希/行数及追问对照来源。`lineAnalysis` 的数值行号仅属于不可变 AC 快照；WA/RE/TLE/候选代码定位写入 `answer`，注明来源并使用函数名或片段。其自报 AC 不自动延伸到对照代码。Schema 的描述同步传给现有 Provider JSON Schema，**没有新增模型输出字段或改数据库结构**。

提示先要求状态/不变量/触发条件/不可恢复原因，再尝试反例；区分源码事实、静态推导、未核验结果。没有可信执行证据通道时，不得把用户声称的运行结果当系统验证。无法构造可信反例时须明确保留未核验状态。容量、单向存储与转移、变量类型和乘法求值分别分析；不把本例答案或有效反例写入 Prompt。

审核移入 `server/review/audit.ts`，保留原 `auditReview` 导出。仍使用严格 JSON、逐字段/总长度、所有段落/行分析/复习问题的声明检查、原 AC 行号范围、已知秘密（含 JSON 转义后的解码值）、危险 HTML/URL 和内部推理限制。未删除输出审核，未原样显示未审核响应。

拒绝仍为 502 与原错误码，只增加由服务端固定枚举产生的安全 `reason`：

| reason | 类别 |
| --- | --- |
| `invalid_schema` | 无效 JSON、未知字段、结构或长度违规 |
| `unsafe_content` | 已知秘密、危险内容、内部推理等；不暴露具体秘密或原文 |
| `invalid_line_range` | 原 AC 行号越界/倒置；正数/整数字段仍由 Schema 验证 |
| `unsupported_execution_claim` | 没有可信执行证据却作正向执行/保证声明 |

HTTP/客户端只接受此枚举，拒绝注入未知 reason。未新增原始响应保存或日志；数据库中丢失的历史输出仍不可恢复。拒绝后仍结算实际 Provider 返回的 usage（成功尝试标 rejected，不写分析），不伪造缺失 token/cost。客户端仅成功后清空问题、替换结果；失败保留追问和旧结果，并提示可能产生用量、由用户检查后决定重试。没有自动重试/自动付费复测。

Provider 的请求次数、超时、JSON Schema、usage 解析、HMAC 受控结算及配额/租约未改；Auth/RLS/CAS/同源和竞赛限制仍由既有链路执行。没有模型切换、推荐权重/同步算法变更或迁移。

## 4. 离线验证工具与隔离

```bash

PYTHONPYCACHEPREFIX=/tmp/algopilot-m352-pycache python3 -m unittest discover -s tests/offline -p 'test_m352*.py'
```

工具为 `scripts/m352-verify-counterexamples.py`，只在开发 CLI 使用；生产 API/Orchestrator 不导入，不提供任意源码路径参数。编译前核验上表两个固定路径及 SHA-256，缺文件/哈希不符/沙箱不可用返回 `unable_to_verify` 并以非零退出，绝不退回无沙箱运行。公开 checkout 不带私有源码，不能冒称 CI 已可独立运行这项原生测试。可选 `--cases` 仅为有大小/数量限制的输入与声明 JSON，不改变被执行的程序。

本轮系统为 macOS、Apple Clang。源码字节不变，在 0700 临时目录复制为 0600 文件编译；测试头 shim 提供 GNU `bits/stdc++.h` 所需标准头。原始诊断若含源码不输出；只报告固定错误类别。编译/运行均在 `sandbox-exec` 禁网络配置下，运行另禁 fork；可信固定探针实测 loopback 连接、fork 被拒绝。无外部网络请求。

运行 CPU 2 秒、墙钟 3 秒，编译 15/30 秒，限制文件描述符、文件大小、core 和进程数。系统拒绝设置 RLIMIT_AS/DATA：首次因此返回“无法核验”，没有照常运行。最终采用父进程 RSS watchdog（运行 256 MiB、编译 1024 MiB），可信 64 MiB 分配探针在测试阈值 8 MiB 被终止。**RSS 是抽样监控，存在采样间隙，且不提供严格虚拟地址空间或整个编译进程树的硬内存保证**；不是 VM/通用恶意代码沙箱，只用于固定、可信的授权夹具。若要求硬内存隔离，须在专用受限环境另验，本轮不新增基础设施。

输入先检查 n/m、边数、端点、无自环/重边等约束；独立 oracle 直接枚举所有严格递增路径及终点原无向度，不照搬提交的 DP。oracle 仅处理 n≤8，大输入明确“无法核验”，不伪造期望值。结果区分：触发 WA、未触发、输入不合法、模型输出陈述错误、无法核验；保留实际行为与声明不符字段，不用“模型陈述错误”掩盖其实没触发 WA。
