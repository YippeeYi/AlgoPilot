## P0：数据安全与完整 MVP 的发布阻塞

| 缺口 | 当前证据/状态 | 下一步与所需条件 |
| --- | --- | --- |
| 原生 PostgreSQL 多连接与 RLS | 现有 20 项 **NOT_RUN**；此前无可复用本地 runtime，PGlite/HTTP 不替代事务锁、连接故障与原生角色验收 | 用户提供安全隔离环境后执行现有专项；遵守此前不下载、不安装、不拉镜像、不启动系统服务的要求，不再自动搜索环境 |
| 托管结构、迁移与真实身份隔离 | 011–013 托管部署/验收未完成；001–010 有历史目录核验，但执行账本曾缺失，不能据此推断当前部署状态。当前目标实际状态 **UNKNOWN/NOT_RUN** | 先明确专用目标、只读核验与变更清单，再取得当前授权。真实签发 JWT、两用户 RLS/归属、Cookie 刷新、撤权时序、HMAC 配置一致性及多连接/多应用实例分别验收；不读取密钥、不自动 repair 或补账本 |
| 免费模型资格和独立生成许可 | 可信免费资格 **BLOCKED**；B4 **NOT_RUN**；本地默认拒绝通过不证明账户免费 | 先建立可信、绑定项目/凭据且有期限的资格证据及独立当前授权，再按批准范围检查真实 Provider/网络/恢复/输出安全与质量、usage/费用。模型名、Flash、环境布尔、历史预算不能放行；禁止付费回退 |

前三项按数据持久化、身份隔离、AI 核心能力排序。带 Tutor/生成式 Review 的完整 MVP 不能仅凭离线 PASS 宣称已可发布。若计划提供明确禁用 AI 的有限试用版，应另行决定产品范围并向用户准确说明，不能自动降低现有完整验收标准。

本轮另有执行审计待归因：两批静态检查各1次网络尝试被离线保护器拒绝，实际受监控外部HTTP/DNS/Key读取均0；后续私有诊断未复现，来源UNKNOWN。两批包装检查保持FAIL，不能用功能全绿替代审计；在对外引用“全部离线检查通过”前必须保留并解释此限制。详细记录见本轮验收报告。
